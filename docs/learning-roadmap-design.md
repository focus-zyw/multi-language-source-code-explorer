本方案将功能收敛为三个问题：如何找到该读的代码，如何保留已经形成的理解，如何判断改动后值得复查哪里。优先扩展现有工作台。第一轮交付不引入多人服务，不执行导入源码。

本文描述整体设计；已实施部分见下方进度，其余仍为拟议方案。成本为相对工程规模，不是工期承诺；产品价值尚需真实阅读任务验证。

实施进度：切片 1「搜索补齐」已完成，包括指标区间、调用方去重计数、SQL 筛选/排序/分页、URL 状态恢复及排行到搜索的联动。使用内存 SQLite 定向测试、临时项目接口集成和浏览器实际操作验证。当前搜索链接不承诺保存扫描快照。

切片 2 已实施：独立 `project_scan_versions` 表记录扫描版本，避免给旧 projects 表直接新增必读列；`learning_bookmarks` 以项目为归属保存完整定位锚点。当前支持书签重定位及变化/缺失/歧义状态、阅读节点/探索根/方向/页签/源码范围恢复。完整锚点表、手工重新关联、选区/滚动和调用树展开恢复尚未实施；阅读位置保存在本浏览器，书签保存在 SQLite。影响分析仍为后续切片。

切片 3 已实施核心个人笔记：独立 learning_notes 表保存节点/选区/项目笔记、标签与学习状态，支持项目列表、本地草稿、版本冲突提示及副本、回收站与恢复。锚点和选区原始证据随笔记保存，不依赖 symbols 删除级联；代码改变后提示核对，不自动覆盖原证据。当前不包含人工重新关联、相互链接和导入导出，后者仍属于切片 4。

## A 重新评估与范围决策

排序依据：阅读任务收益、现有实现复用程度、结论可验证性、长期维护成本。功能演示容易不代表达到可靠可用的成本低。

- **智能搜索：P0，低至中等。** 已有类型、语言、路径、装饰器、基类、弃用筛选。补指标过滤、排序、结果恢复。首版不引入完整查询语言或正则。
- **阅读位置、书签与快捷键：P0，低至中等。** 阅读位置与书签直接减少重复定位。先支持搜索、帮助、引用跳转；键位要避让编辑器和输入框。
- **学习注解：P1，中等。** 最符合学习资产积累。先做个人笔记、代码引用、状态和导出。多人共享为独立后续范围。
- **影响分析：P2，中等。** 复用反向调用，提供有界的潜在影响查询和测试建议。不要承诺完整行为影响或最小必跑测试集。
- **复杂度热力图与仪表板：并入 P0，增量成本低。** 已有分布与排行，扩展筛选和定位即可。认知复杂度另行实现；覆盖率、趋势不能从当前数据直接得出。
- **相似性检测：P3，中等。** 限定同语言的 token/AST 结构相似。任意逻辑等价和跨语言语义相似为高成本目标。
- **文档同步：P3，规则版低至中等。** 先核对参数标签与签名。注释语义是否过期仍需人工或 AI 辅助。
- **调用栈历史：拆分。** 用户阅读历史纳入 P0；静态参数映射后续单做。运行变量快照需要执行数据。
- **Git 时间线：按需，中等至高。** 先文件或方法附近提交差异，再考虑方法跨版本追踪。
- **跨语言调用：按需，高。** 选择一种具体协议做连接器，不建设通用跨语言解析器。
- **签名建议：低优先级，规则版成本低。** 作为可解释阅读提示，不作为自动设计诊断。
- **性能启发式：低优先级，中等。** 标记待核实模式，不能据此断言运行瓶颈。
- **代码生成建议：暂缓，中等至高。** 依赖可靠的相似性与上下文判断，先服务理解。
- **单测执行：独立立项，高。** 改变静态分析边界。可先支持读取外部生成的报告，但报告关联与来源版本也需设计。

本轮明确不纳入：健康总分、真实覆盖率推测、实时多人协作、自动运行测试、自动修改导入代码。它们均不作为上述阶段验收的隐藏前提。

## B 当前实现依据与架构取舍

已核实的基础：

- `src/lib/project-insights.ts` 的 `buildLearning` 已计算复杂度分布及三个前 20 排名；`LearningOverview.tsx` 已展示。
- `src/lib/symbol-search.ts` 已处理结构化条件；`symbol-search-query.ts` 当前读取全项目文件与符号，再在内存中过滤和分页。
- `src/lib/call-tree-query.ts` 已有 incoming 查询；现有调用树是交互式逐层展开，并非项目影响集合计算器。
- `src/lib/analysis/tests-link.ts` 的间接关联只传播一层，且每个测试有数量限制；`indirect` 没有完整表达沿途可信度。
- `src/lib/analysis/types.ts` 有圈复杂度、参数数、行数，没有认知复杂度。
- `src/components/Workspace.tsx` 管理 URL，根方法与当前方法分开；部分面板状态仍在组件内。
- `src/lib/questions-server.ts` 保存项目级问答，但同名歧义身份包含临时符号 ID；不能原样作为笔记长期身份。
- `src/lib/ingest/pipeline.ts` 在事务中删除旧文件并重建符号、引用和测试关联，项目身份保留。
- 当前符号上限为约 8 万；新增搜索设计应验证接近该规模的数据，而不能只用示例项目。

采用三个模块边界：查询模块负责搜索与影响分析；学习资产模块负责笔记、书签和链接；定位模块负责跨扫描解析锚点。定位模块返回明确状态，不直接删除资产，也不修改笔记正文。

首版只为用户实际保存的目标建立长期锚点，不给每个符号预建永久身份。AI 讲解缓存继续使用现有指纹机制；人工笔记另有保留语义。避免一次性重构全部查询、缓存和问答。

增加项目 `scanRevision`，使用单调递增整数。首次迁移给已有项目初始化版本，之后只在扫描成功提交时递增。失败扫描不递增。搜索、资产定位、影响结果返回该版本，客户端拒绝混用不同扫描版本的符号 ID。

解析规则另记录 `analysisVersion`。扫描版本描述快照变化，分析版本描述算法变化，两者不混用。暂不因为新增版本字段就保存全部历史源码。

## C P0：搜索、阅读恢复与工作台交互

沿用文件树、源码/探索区、右侧详情区和项目总览。现有视觉风格保持一致，不新增一套首页或健康仪表板。

**搜索交互**

在“结构化搜索”增加圈复杂度、源码行数、参数数区间，以及确定调用方数量。默认显示表单条件，条件可组合。示例任务是“TypeScript、非测试、圈复杂度至少 10、至少两个确定调用方”。`cc>10` 简写语法可作为后续便利层。

支持按名称、复杂度、行数、调用方数排序；同值用路径、位置、符号 ID 保证当前快照内稳定顺序。每页 40 条。函数/方法才参与方法度量筛选；结构节点和类不以零值混入。无效条件返回明确错误。

调用方采用 `COUNT(DISTINCT ownerSymbolId)`；确定、推断、候选分别计数，不将三个桶直接相加。高引用表示结构性连接多，不表示执行频繁。

拟扩展现有 GET 搜索接口，字段采用 `minCc/maxCc`、`minLoc/maxLoc`、`minParams/maxParams`、`minExactCallers`、`sort`、`order`。路径和名称继续保持当前大小写不敏感子串语义。将筛选、排序、分页下推至 SQLite；度量先读取现有 JSON 字段，调用方使用按项目限定的聚合查询。

所有值参数化，排序字段白名单化。先对现有 JSON 查询与关联索引测量；仅在测量表明必要时增加度量投影列或复合索引。不预先维护第二套度量事实。

**导航与恢复**

搜索条件、分页与排序写入 URL，由 Workspace 合并已有参数；搜索返回时恢复结果。新增参数使用命名空间，避免与当前方法 `s`、调用树根 `root`、来源等冲突。

本浏览器保存最近阅读状态：扫描版本、方法定位信息、探索根定位信息、方向、页签、源码模式、选区和滚动位置。长期书签保存到 SQLite；临时视图状态保存到本地存储，并限制记录体积。

明确带目标的 URL 优先于恢复记录；没有目标的项目入口展示“继续上次阅读”，由用户点击恢复。跨扫描先解析当前方法和探索根，分别处理失效；不能直接使用旧 ID。

同一快照下恢复调用树展开状态；重扫后首版只恢复可定位的根与当前方法，旧展开路径清空并提示。这样不会假装旧调用点仍有效。

快捷键首版只提供搜索、帮助、上/下引用；浏览器原生前进后退继续工作。输入框、可编辑区和 Monaco 聚焦时不抢字符键。重扫保留显式入口。

**学习概览**

已有排行增加“查看全部符合条件的方法”，跳转到对应搜索。显示当前快照时间、解析失败、未解析关系和截断情况。暂不增加综合质量分。

## D P1：个人学习笔记与持久化设计

**入口与流程**

方法标题提供“收藏”“记笔记”；选中源码后提供“为选区记笔记”。右侧新增“笔记”页签，项目总览新增“学习记录”，集中查看书签、笔记、待确认项及待重新关联项。

笔记包含正文、标签、学习状态、目标代码与可选引用。学习状态是用户的“待阅读/阅读中/已理解”；它与代码引用是否过期分开展示。源码改变不会自动取消用户的理解状态。

先支持方法、测试、HTML/JSON 节点笔记与链接。结构节点用其结构身份定位，不套用复杂度或调用分析。手工排序的阅读路线在核心笔记验收后增加。

**数据结构（拟新增）**

- `learningAnchors`：UUID、projectId、locatorVersion、相对路径、语言、kind、限定名称或结构路径、签名提示、创建时是否唯一、原始源码摘要、有限选区文本及上下文、原始相对位置、当前绑定信息与解析版本。
- `learningNotes`：UUID、projectId、anchorId 可空、标题、Markdown 正文、标签、学习状态、noteVersion、createdAt、updatedAt、deletedAt。无目标的项目笔记也可存在。
- `learningBookmarks`：UUID、projectId、anchorId、用户标题、createdAt；同项目同锚点避免重复收藏。
- `learningLinks`：UUID、projectId、源笔记、目标笔记或目标锚点、关系说明。引用目标保存 UUID，点击时解析当前源码。
- 可选后续 `learningPaths/learningPathSteps`：路线 UUID、标题、版本；步骤记录位置、目标锚点或笔记及“为什么读这里”。重排事务化。

笔记、书签只能随显式删除项目而级联清理，不能依赖 symbols/files 的删除级联。当前绑定 symbolId 只是可失效缓存。它不作为笔记主身份，扫描替换时明确清空并重新解析。

锚点的“原始证据”不被自动覆盖。用户选择“已核对新版本”时更新核对基线并保留原始信息。移动目标通过显式重新关联处理，记录原定位、目标定位和时间。

**保存、并发和草稿**

首版使用显式保存及 Ctrl/⌘+Enter，正文变更立即形成有大小限制的本地草稿。状态显示“未保存/已保存/保存失败”。切换目标时草稿按笔记或新建草稿 UUID 隔离，不能串入其他方法；存储失败时明确提示，不能假装已经保留。

创建请求带客户端 UUID 作为幂等键；重复发送返回同一笔记。更新使用 `noteVersion` 乐观并发校验，冲突返回 409 并同时保留本地文本与服务器版本，不静默覆盖。

保存正文不依赖最新扫描。若保存时定位版本已变，正文仍能持久化，锚点标为待核对；新增锚点必须由服务端核实原扫描目标，版本不匹配时先持久化为未绑定笔记，再提供重新定位。

普通删除进入回收站，支持恢复；首版不自动清空回收站。项目删除仍按现有项目删除语义处理，界面说明将同时删除学习记录。

**接口（拟新增，均在项目作用域下）**

- `GET/POST /api/projects/:id/notes`：分页列表、创建。
- `PATCH/DELETE /api/projects/:id/notes/:noteId`：版本化更新、移入回收站；补恢复操作。
- `POST /api/projects/:id/anchors/resolve`：有界批量解析并返回状态、扫描版本。
- `POST /api/projects/:id/anchors/:anchorId/rebind`：用户确认目标后重新关联。
- `GET/POST/DELETE /api/projects/:id/bookmarks[...]`：收藏操作。
- `POST /api/projects/:id/learning/import-preview` 与 `.../import`：先校验预览再写入。
- `GET /api/projects/:id/learning/export`：导出所选记录。

写接口复用本机来源验证逻辑，但笔记正文限额独立设置，不能直接套导入接口的 8KB 限额。建议正文最多 32KB，导入包最多 10MB、1000 条；这些是待测试的产品限额。服务端核实项目归属、链接目标、请求体实际大小和字段版本。

Markdown 默认禁用原始 HTML，拒绝脚本 URL；导出默认不带源码片段，可显式勾选。JSON 用于完整往返，Markdown 用于阅读分享。导入要求用户选择当前项目，按包内 UUID 重写引用；相同记录相同内容跳过，内容冲突默认保留副本。陌生绝对路径不得触发文件读取。

## E 重扫后定位：正确保留比自动匹配更重要

定位结果使用两个独立维度：

- 位置状态 `resolved / missing / ambiguous`：能否唯一绑定到当前节点。
- 内容状态 `unchanged / changed / unknown`：现有证据相对用户核对基线是否变化。

算法按顺序执行：

1. 同一扫描版本且缓存目标属于该项目，复用绑定。
2. 按项目、相对路径、语言、kind、限定名称或结构路径找候选。
3. 创建时和当前均唯一，可绑定节点；摘要相同标 unchanged，不同标 changed。
4. 同名有歧义时，只有原始源码摘要与辅助证据共同得到唯一匹配才可绑定。签名相似和最近行号不能独立成为依据。
5. 移动或重命名仅给出候选，首版要求手动重新关联。缺失或歧义记录仍显示在项目学习记录中。

选区定位在节点绑定后独立处理：节点内容未变时使用方法内相对位置；内容变了则用选区文本和前后文寻找唯一匹配。找不到或重复匹配时保留笔记并显示原引用，停用精确源码跳转。旧绝对行号不能直接套到新内容。

扫描流程保持原子性：在现有写事务内替换分析数据、递增 scanRevision，并使旧锚点绑定失效；失败则全部回滚。昂贵的锚点匹配在读取时按批次懒执行，避免重扫事务被笔记数量拖长。解析缓存回写须核对扫描版本，防止晚到结果覆盖新快照。

不把源码摘要当作永久身份：两处复制代码可以有相同摘要，一处代码改了也仍应保留原笔记。结构定位、证据和用户判断共同决定归属。

## F P2：潜在影响分析与测试建议

**交互**

方法菜单增加“查看潜在影响”，进入现有探索区的影响视图。左侧为调用方与测试建议列表，右侧可切换关系图和证据路径。点击证据定位具体调用点。根方法与当前查看方法继续分开。

提示文案为“当前静态快照中可能需要复查的范围”。确定边沿用现有可信度样式，额外用边框强调影响候选；不要把所有节点涂红而遮蔽边的可信度。

**算法与边界**

服务端按目标函数建立反向调用查询，逐层批量读取当前 frontier 的调用方。默认只沿 exact 边；用户可加入 inferred。heuristic 仅作候选附录，首版不递归扩散。

路径可信度取沿途最弱等级。用 `(symbolId, pathConfidence)` 记录遍历状态，避免先经推断路径访问后遗漏更强路径。循环停止扩展；同一个方法只占一条结果，但保留不同可信度的代表证据。每个可信度优先保留最短路径。

建议初始默认深度 3、最大 8，最多 500 个结果节点、2000 条边；每个方法最多 3 条代表证据。限制需结合基准调整。返回停止原因、已探索深度和已知数量，不把已探索结果数说成全项目总量。限额约束遍历和读取过程，而不是读完全项目后再截断。

查询在一致快照的只读事务内执行；返回 scanRevision。重扫后结果失效，重新查询；不持久保存跨版本 symbolId 图。

**关联测试**

从反向调用路径到达的测试，展示完整证据；现有 testLinks 补充命名候选和一层间接线索。同一个测试去重，但保留来源。

`indirect` 表示路径长度而非置信等级。现有间接关联若无法重建沿途证据，展示“已有间接关联，路径未完整核实”，不得升级成确定。命名候选单独展示，不参与确定路径计数。

测试列表名为“建议复查的关联测试”；零结果写“未找到静态关联测试”。不生成覆盖率、最小测试集或“其余测试无需运行”的结论。

**接口与扩展**

拟新增 `GET /api/projects/:id/symbols/:sid/impact?confidence=exact&depth=3`。返回 nodes、edges、testSuggestions、evidence、limits、scanRevision。API 核实符号项目归属并限制查询参数。

共享状态、事件注册、动态反射与项目外调用可能漏检，作为该快照的分析盲区说明。后续若增加跨语言连接器，它输出有证据的独立边类型；未经验证不混入普通确定调用边。

## G 后续设计、实施切片与验收

**P3 相似性与注释检查**

相似性首版限定同语言函数/方法，过滤过短方法和生成产物。先用归一化 token 指纹找候选，再比较 token 序列或 AST 结构。保留严格匹配与忽略标识符匹配两种模式，字面量差异可见；相似分数不作为逻辑等价概率。

结果是候选片段、差异与匹配理由。采用大小分桶和指纹索引限制候选，避免全部方法两两比较。首批只实现一至两种语言，语言适配另行验收。

文档首版选择明确格式，例如 JSDoc 参数标签和一种 Python docstring 格式，检查参数增删与重复标签。不要求所有 void 方法有返回文档；语义一致性检查显示“建议人工核实”。

**可独立交付的切片**

1. 搜索补齐：指标筛选、排序、URL 恢复和已有排行联动。
2. 定位基础：scanRevision、有限锚点、书签与阅读位置恢复。
3. 个人笔记：保存、冲突处理、选区引用、重扫状态、回收站。
4. 学习资产流转：JSON 导入导出、Markdown 导出、链接和手工阅读路线。
5. 潜在影响：有界反向遍历、可信度证据、测试建议。
6. 后续能力：相似片段、文档规则，其他功能由实际使用需求触发。

前两个切片优先交付；核心笔记的定位与保存验收通过后，再扩展路线与导入导出。影响分析可复用扫描版本，但不依赖笔记功能上线。拆分模块不代表需要微服务。

**关键验收用例**

- 搜索：组合条件、区间边界、零调用方、可信度分桶、稳定分页、结构节点排除；浏览器后退恢复查询。
- 定位：文件前插行、方法体改变、同名重载、相同复制代码、移动、删除；失败重扫时笔记和原分析都可用。
- 保存：切换方法后草稿不串内容；重复提交不创建副本；双标签编辑冲突不丢正文；扫描与保存交错不会误绑目标。
- 导入：同包重复导入、冲突副本、未知 schemaVersion、跨项目引用、损坏及超限包、脚本链接；失败时事务回滚。
- 影响：A→B→C 修改 B 能查到 A；不因此宣称 C 被修改影响。覆盖循环、菱形、多可信度路径、候选不扩散、限额和扫描版本变化。
- 生成生命周期：离开笔记或影响视图不取消已有讲解/问答；真实任务不用于测试夹具。

性能以人工生成的独立项目测试：约 1 万与接近 8 万符号两个规模，记录边数、机器配置、冷/热查询的 p50/p95、内存和扫描耗时。首版目标是热搜索 p95 不超过 500ms、有界影响查询不超过 2s；这是设计预算，不是已经测得的性能。未达标先定位查询或布局瓶颈，不静默缩减结果。

模块纯逻辑用 node --test 验证；数据库测试使用临时 SQLite 和临时项目；页面验证实际操作。实现时按仓库约定执行 typecheck、改动文件 ESLint、相关测试和 build。仅设计文档变更不运行应用构建。测试涉及模型时一律使用模拟后端。

## H 成功标准与证据说明

第一轮试用采用四个任务：找到指定条件的方法；跟随调用关系并返回原位置；记录理解后重扫并找回；查看一个方法的潜在影响并说清依据。记录任务是否完成、重复定位次数、误解分析结论的情况与耗时。先建立基线，再确定改善目标，避免虚构收益百分比。

首版的产品成功标准是：用户能更顺畅地阅读，并信任保存的理解仍可找回。复杂度数量、笔记数量或图节点数量本身不作为成功指标。

本地代码证据见 B 节；所有新表、接口、阈值和交付切片均为本方案建议。技术概念依据：

- [Sonar 指标定义](https://docs.sonarsource.com/sonarqube-server/10.6/user-guide/code-metrics/metrics-definition)：圈复杂度与认知复杂度分开计算。
- [Coverage.py 原理](https://coverage.readthedocs.io/en/7.14.0/howitworks.html)：覆盖数据来自执行测量；静态分析确定可执行位置。
- [PMD CPD](https://pmd.github.io/pmd/pmd_userdocs_cpd.html)：复制检测有标识符、字面量等匹配配置；不能由此推出语义等价。

当前设计不需要选择云服务、向量数据库或外部账户。新增持久表采用显式、可重入的增量迁移，迁移失败阻止相关写入，保留现有数据；发布前以旧库副本验证升级。重扫不作为迁移用户笔记的替代方案。
